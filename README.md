# From a Biological Question to Data

Companion code for **Article 2** of *Research to Production - Data Science Biologist* on Research to Production (`https://research-to-production.beehiiv.com/`).

The question the whole analysis serves:

> **Can measurements taken from a breast tumour sample be used to distinguish a malignant tumour from a benign one?**

## Quickstart

```bash
# 1. An environment for this project alone
python3 -m venv .venv
source .venv/bin/activate            # Windows PowerShell: .venv\Scripts\Activate.ps1

# 2. Four packages, and only four
pip install --upgrade pip
pip install pandas matplotlib jupyterlab ipykernel

# 3. Make Jupyter use *this* Python, not some other one
python -m ipykernel install --user --name research-to-production

# 4. Go
jupyter lab
```

Open `exploratory_data_analysis.ipynb`, switch to the **research-to-production** kernel (Kernel → Change Kernel), and run the cells top to bottom.

| Package | Why |
| --- | --- |
| `pandas` | the DataFrame — tables with named columns and typed values |
| `matplotlib` | every figure |
| `jupyterlab` | the notebook interface |
| `ipykernel` | lets Jupyter run code inside this environment |

You also need **`curl`** for the download in section 1. It ships with macOS, virtually every Linux distribution, and Windows 10 and later.

Step 3 is the one people skip, and it produces the most baffling error in early data science: `ModuleNotFoundError: No module named 'pandas'` *immediately after* watching pip install pandas. Section 0 of the notebook ends with a cell that prints which Python is actually executing your code — check that first whenever an import mysteriously fails.

## The notebook

`exploratory_data_analysis.ipynb` goes from a URL to a dataset you understand, in seven short sections:

- **0. Set up your environment** - one virtual environment per project, and how to point Jupyter at it
- **1. Get the data** - download the zip from UCI, unpack it, check you got data and not an error page
- **2. Look at it before you load it** - `head`, `tail`, `wc`, `grep`, `cut`, `awk`, `sed`, and the documentation
- **3. Hello world, with real data** - read the file with plain Python before reaching for a library
- **4. First look in pandas** - supply the column names, load, check shape and dtypes
- **5. Summary statistics** - missing values, `describe()`, group means by diagnosis
- **6. Explore the biology in the data** - histogram, box plots, scatter, correlation matrix

Section 2 is the one most tutorials skip, and it is how you discover that this file has **no header row** and that field 2 is the diagnosis - neither of which is guessable.

The notebook is committed with its outputs saved, so it reads without running.

## The data

The **Wisconsin Diagnostic Breast Cancer** dataset: 569 samples, one per fine-needle-aspirate image, one image per patient. 30 features - ten nuclear measurements, each reported as its mean across nuclei, its standard error, and its "worst" value (the average of the three largest). 357 benign, 212 malignant. No missing values.

These are measurements of **cell nuclei, not of the tumour**. A `radius_mean` of 17.99 is not an 18 mm lump; it is the average size of nuclei in a microscope image.

Section 1 downloads it from the UCI Machine Learning Repository, dataset 17:

```
https://archive.ics.uci.edu/static/public/17/breast+cancer+wisconsin+diagnostic.zip
```

The extracted `wdbc.data` should be 124,103 bytes, md5 `c6dd5a2909808f3a901cf00cfd8dfff0`.

**If the download fails** - UCI's servers are not always reliable - the two files are also served individually at the older path, which needs no unzipping:

```bash
BASE="https://archive.ics.uci.edu/ml/machine-learning-databases/breast-cancer-wisconsin"
curl -fLo data/wdbc.data  "$BASE/wdbc.data"
curl -fLo data/wdbc.names "$BASE/wdbc.names"
```

Only the *file* URLs resolve there; opening the folder above them in a browser returns a 404, which looks like a dead link and is not one.

**One source to avoid.** UCI also publishes a tidied `data.csv` for this dataset. Same 569 samples, but it has a header row, the columns are renamed `radius1`/`radius2`/`radius3`, and the diagnosis has moved to the last column. Nothing in this notebook works on it unchanged.

This is a teaching set from one hospital in the early 1990s, with no patient context and no documented units. **Nothing here is for clinical use.**
